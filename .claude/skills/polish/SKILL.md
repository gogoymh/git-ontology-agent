# polish

에이전트가 쓴 글을 사람이 쓴 말처럼 고친다. 뜻은 바꾸지 않는다.

## 지키는 것

- 이름, 티켓 번호, 경로, 명령, 숫자는 그대로 둔다.
- 없던 주장을 더하지 않고, 있던 사실을 빼지 않는다.
- 한 문장에 한 가지만 말한다. 쉼표는 한 문장에 하나까지 쓴다.
- 결과를 먼저 쓰고, 방법은 그다음에 쓴다.

각 패턴의 예는 최근 #general 알림에서 그대로 가져왔다. `전:`은 원문, `후:`는 고친 문장이다.

## 1. 상투적인 착수 이유

"가장 명확한 작은 작업입니다", "가장 시급합니다", "명확하고 완결된 작업" 같은 말은 왜 맡았는지 알려 주지 않는다. 같은 말이 매번 나오면 읽는 사람이 건너뛴다. 무엇이 문제이고 왜 지금 할 수 있는지를 사실로 쓴다.

- 전: 미션 GOA-11(으)로 맡았습니다. 사용자 결정이나 외부 설정 없이 README에 한국어 소개 PPT 링크와 생성 명령만 추가하면 바로 완료할 수 있는 가장 명확한 작은 작업입니다.
- 후: GOA-11을 맡았습니다. README에 한국어 소개 PPT 링크와 생성 명령만 넣으면 끝나고, 사용자 결정이나 외부 설정이 필요 없습니다.

- 전: 미션 GOA-20(으)로 맡았습니다. CI에서 누락된 README와 소개 덱 검증을 추가해 문서·링크 회귀를 바로 막을 수 있는 가장 명확하고 완결된 작업입니다.
- 후: GOA-20을 맡았습니다. 지금 CI는 README와 소개 덱을 검사하지 않아서 문서나 링크가 깨져도 모릅니다. 검사를 더하면 바로 막을 수 있습니다.

- 전: 미션 GOA-14(으)로 맡았습니다. 재시작이나 모델 변경 시 진행 중인 req/* 요청이 유실되는 문제를 고치는 것이 가장 시급합니다.
- 후: GOA-14를 맡았습니다. 재시작하거나 모델을 바꾸면 진행 중인 req/* 요청이 사라집니다. 이것부터 고쳐야 합니다.

- 전: 미션 GOA-17(으)로 맡았습니다. 최근 병합된 재시작 이어받기 기능에서 이전 대화 기록이 화면에 복원되지 않는 UX 공백을 명확한 범위로 바로 해결할 수 있습니다.
- 후: GOA-17을 맡았습니다. 재시작 이어받기가 병합됐지만 이전 대화 기록이 화면에 돌아오지 않는 UX 공백이 남았습니다. 범위가 분명해서 바로 고칠 수 있습니다.

## 2. 쉼표로 길게 늘어놓는 완료 보고

한 문장에 기능을 쉼표로 서너 개 잇고 "~하도록 구현했습니다"로 끝내면, 무엇이 달라졌는지 찾기 어렵다. 사용자가 보게 될 변화를 첫 문장에 쓰고, 나머지는 한 문장에 하나씩 나눈다. 가운뎃점은 쓰지 않는다. 명사 둘은 '와'나 '과'로 잇고, 셋 이상이면 쉼표 하나와 '와'로 묶거나 문장을 나눈다.

- 전: goa serve가 시작할 때 main, 열린 req/*, cancelled/req/*, answers 브랜치에서 최근 대화 기록을 읽어 history 이벤트로 보내고, UI가 이를 시간 순서대로 복원해 표시하도록 구현했습니다. /connect 재연결 시 중복 출력을 막고 재시작 복원 단위 테스트와 UI 통합 테스트를 추가했습니다.
- 후: 이제 goa serve를 다시 켜도 이전 대화가 화면에 시간 순서대로 돌아옵니다. 시작할 때 main과 answers, 열린 req/*와 cancelled/req/* 브랜치에서 최근 기록을 읽어 history 이벤트로 보냅니다. /connect로 다시 연결해도 같은 내용이 두 번 나오지 않습니다. 재시작 복원 단위 테스트와 UI 통합 테스트를 더했습니다.

- 전: 엔진이 시작할 때 머지되지 않은 req/* 브랜치와 커밋 이력으로 열린 작업, 요청 번호, 시계를 복원해 남은 단계를 마치고 main에 머지합니다. goa serve 시작 직후 열린 tasks를 보내고, 터미널 UI에서 /connect로 모델을 바꿀 때 이전 엔진이 종료된 뒤 새 엔진을 열어 충돌 없이 이어서 처리합니다.
- 후: 이제 재시작해도 진행 중이던 요청이 이어서 처리됩니다. 엔진은 시작할 때 머지되지 않은 req/* 브랜치와 커밋 이력에서 열린 작업과 요청 번호, 시계를 되살립니다. 그리고 남은 단계를 마쳐 main에 머지합니다. goa serve는 켜지자마자 열린 tasks를 보냅니다. 터미널 UI에서 /connect로 모델을 바꾸면 이전 엔진이 끝난 뒤에 새 엔진이 열립니다. 그래서 충돌 없이 이어집니다.

- 전: CI에 docs 잡을 추가해 README 검사, README 로컬 링크 대상 존재 검사, 소개 덱 검사 4종(valid·count·korean·story)을 돌립니다. 덱이 손상되면 검사가 트레이스백 대신 명확한 오류로 실패합니다.
- 후: CI에 docs 잡을 더했습니다. 이 잡은 README와 README가 가리키는 로컬 파일을 확인합니다. 소개 덱은 valid와 count, korean과 story 4가지로 검사합니다. 덱이 손상되면 트레이스백 대신 무엇이 틀렸는지 알려 주는 오류로 실패합니다.

## 3. 확정하지 않은 조사 표기

을(를), 이(가), 은(는), 와(과), (으)로는 서식 틀이 받침을 모를 때 쓰는 표기다. 사람은 이렇게 쓰지 않는다. 앞말을 소리 내어 읽고 끝소리에 맞는 조사 하나만 쓴다.

- 받침이 있으면 앞 형태(을 이 은 과 으로), 없으면 뒤 형태(를 가 는 와 로)를 쓴다.
- ㄹ 받침 뒤에는 '으로'가 아니라 '로'를 쓴다. (GOA-17 → 칠 → GOA-17로)
- 숫자는 읽는 소리로 판단한다. 1 일, 3 삼, 6 육, 7 칠, 8 팔, 10 십, 0 영은 받침이 있고 2 이, 4 사, 5 오, 9 구는 없다.
- 영어 이름도 읽는 소리로 판단한다. Antigravity(안티그래비티)와 Claude(클로드)는 받침이 없다.
- 코드에서 조사를 붙일 때는 앞말의 마지막 소리를 보고 고른다. 한글 음절은 `(code - 0xAC00) % 28`이 0이면 받침이 없고 8이면 ㄹ 받침이다.
- "미션 GOA-23(으)로 맡았습니다"처럼 조사가 어색하게 걸리면 문장을 "GOA-23을 맡았습니다"로 바꿔 조사를 하나로 정한다.

- 전: 미션 GOA-14을(를) 마쳐 병합했습니다.
- 후: GOA-14를 마치고 병합했습니다.

- 전: Antigravity이(가) 사용 한도에 닿아 미션 GOA-15을(를) Claude(으)로 이어서 합니다.
- 후: Antigravity가 사용 한도에 닿아 GOA-15를 Claude로 이어서 합니다.

- 전: 미션 GOA-17을(를) 끝내지 못하고 멈췄습니다. 미션 화면에서 확인해 주세요.
- 후: GOA-17을 끝내지 못하고 멈췄습니다. 미션 화면에서 확인해 주세요.

- 전: 미션 GOA-23(으)로 맡았습니다.
- 후: GOA-23을 맡았습니다.

## 고친 뒤 확인

- `후:` 문장에 원문의 이름, 번호, 경로, 명령이 모두 남아 있는가.
- 을(를)이나 (으)로 같은 병기 표기가 남지 않았는가.
- 가운뎃점이 남지 않았는가.
- 쉼표가 두 개 이상인 문장이 없는가.
- "가장 명확한", "가장 시급한", "완결된" 같은 말 없이도 이유가 전해지는가.
